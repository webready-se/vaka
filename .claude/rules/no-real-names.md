# No real names in git or on GitHub

**The rule:** nothing that names a real person, customer, site, domain, server, IP, Slack channel, webhook or service account goes into this repository: not in code, tests, fixtures, docs, screenshots, commit messages, PR or issue titles and texts, comments or releases. Use the reserved examples (`shop.example`, `example.com`, `203.0.113.10`, "Customers", "Agency") instead.

**Why:** the repository will be public, and git keeps everything: a name in an old commit message or a PR text is as public as one in the code, and taking it out later means rewriting history. Editing a PR text does not help either: GitHub keeps its earlier versions. It slips in most easily in text written while looking at production data ("the dashboard said ... for <real domain>"): describe the case with example names instead.

The risk starts the day real data enters the work, not before. Until go-live Vaka only knew fake sites and nothing slipped; on go-live day, with the rule already in place, six commit messages, one test and eight PR texts named real sites, a customer, a server and a registrar. A rule alone did not hold, hence the hooks.

**How it is enforced** (so it does not depend on remembering):

- `.private/real-names.txt` (gitignored) lists the real names: the sites from the real site list, servers, IPs, customers and services. Keep it up to date when sites or servers change. The hooks match text, so an international domain goes in both spellings (`xn--...` and as written, the way the dashboard shows it), and a removed site stays in the list (old notes still name it). å, ä and ö match in either Unicode form (one character, or a letter and a combining mark, as macOS sometimes writes them): `scripts/hooks/real-names` brings the list and the text to NFC first.
- `scripts/hooks/pre-commit` stops a commit that adds a line with one of them; `scripts/hooks/commit-msg` stops a commit message with one; `scripts/hooks/pre-push` checks what a push sends to GitHub: branch and tag names, tag messages, and the messages and added lines of every commit not yet on the remote (so a name added to the list later still stops the push). All use `scripts/hooks/real-names`, and `composer install` turns them on (`core.hooksPath`).
- `.claude/hooks/no-real-names.sh` (PreToolUse) stops a `gh` command that sends text to GitHub (`pr` and `issue` create/edit/comment/review/merge/close, `release` and `repo` create/edit, `gist`, and every `gh api` call) when the text, inline or in a file (`--body-file`, `-F`, `--notes-file`, `--input`, `-F field=@file`), contains one. A merge made on GitHub writes its commit there, past the git hooks, so `gh pr merge --subject/--body` is checked here. Local paths in the command are not checked (they never reach GitHub); give files as paths without shell variables, so the hook can read them. It reads the whole command line, so a name in a command next to `gh` (`curl <site> && gh pr create ...`) stops it too: run `gh` on its own. Splitting the line into its commands and reading only the `gh` ones was considered and declined (2026-10-27): it saves a rare false alarm, and a mistake in parsing the shell would let text through instead of stopping it.
- Without `.private/real-names.txt` (a fresh clone, a contributor) nothing is checked: the list is what is private.

When a hook stops you, rewrite the text with example names. Never bypass it with `--no-verify`, and never weaken the list to get a commit through.
